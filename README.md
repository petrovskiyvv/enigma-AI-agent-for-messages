# ENIGMA HACK: AI-агент технической поддержки "ЭРИС"

## О проекте

Данный репозиторий содержит предварительную реализацию решения для хакатона ENIGMA HACK. Цель проекта — разработать AI-агента, который автоматизирует обработку входящих писем в службу технической поддержки, извлекает ключевые данные, классифицирует обращения и генерирует ответы на основе базы знаний.
В качестве основного стека мы используем связку Python (FastAPI) для быстрого и надежного бэкенда, PostgreSQL для хранения данных  и Flutter (Web) для создания отзывчивого кроссплатформенного интерфейса оператора.

---

## 1. Пользовательский путь (User Journey)

Взаимодействие оператора технической поддержки с системой построено по следующему сценарию:
1. **Вход и мониторинг:** Оператор открывает веб-приложение (написанное на Flutter) и видит главную таблицу обращений, которая обновляется в реальном времени.
2. **Оценка ситуации:** В таблице сразу видны ключевые данные из новых писем: ФИО, объект, суть вопроса, номера приборов и эмоциональный окрас письма (позитив/нейтраль/негатив).
3. **Обработка заявки:** Оператор кликает на новую строку в таблице. Открывается детальная карточка обращения.
4. **Проверка работы AI:** В карточке отображается исходный текст письма, автоматически определенная категория (например, "калибровка" или "неисправность") и сгенерированный AI-агентом черновик ответа, основанный на руководствах и FAQ.
5. **Редактирование и отправка:** Оператор проверяет черновик, при необходимости вносит корректировки и нажимает кнопку «Отправить».
6. **Завершение:** Система отправляет письмо клиенту, сохраняет итоговый ответ в историю (PostgreSQL) для дообучения базы знаний и меняет статус заявки на "Закрыто".

## 2. Архитектура системы

Система состоит из независимых микросервисов, взаимодействие между которыми описано ниже:
* **Модуль интеграции с почтой (IMAP/SMTP):** Фоновый Python-воркер, который безопасно подключается к почтовому ящику саппорта по IMAP, скачивает новые письма и передает их в ядро приложения. Отправка готовых ответов происходит через SMTP.
* **Ядро AI-агента (FastAPI):** Основной бэкенд. Получает текст, очищает его и передает в NLP-модели (Hugging Face Transformers). Модели извлекают сущности (NER для номеров приборов, контактов) и определяют тональность.
* **База знаний и RAG (Retrieval-Augmented Generation):** Бэкенд ищет релевантные куски текста в векторном представлении руководств по эксплуатации и FAQ для формирования контекста.
* **Генерация ответа:** На основе контекста из базы знаний и классификации запроса формируется итоговый шаблон или кастомизированный текст ответа.
* **База данных (PostgreSQL):** Хранит структурированные данные о письмах (согласно требуемой схеме), логи обращений и базу знаний. Изолирована в отдельном контейнере для безопасности и удобства администрирования.
* **Frontend (Flutter Web):** Клиентское приложение. Общается с FastAPI через REST API. Отвечает за отрисовку веб-таблицы, экспорт в CSV/XLSX и предоставление удобного интерфейса оператору.

## 3. Анализ рисков

В условиях ограниченного времени хакатона мы выделяем следующие основные риски и способы их минимизации:
| Описание риска | План минимизации |
| --- | --- |
| **Низкая точность извлечения специфичных заводских номеров** из неструктурированного текста с помощью NLP. | Реализация возможности ручной корректировки всех полей оператором в интерфейсе Flutter до финального сохранения в базу. |
| **Сложности интеграции и "падение" окружения** при объединении ML-моделей, базы данных и бэкенда. | Строгая изоляция сервисов через Docker и `docker-compose`. Все зависимости фиксируются заранее, среда разворачивается одной командой. |
| **Блокировка почтового ящика** провайдером из-за частых запросов по IMAP в процессе тестирования. | Использование заглушек (mock-данных) JSON на этапе активной разработки бэкенда. Подключение реального IMAP только на финальной стадии интеграции. |
| **Нехватка времени на разработку сложной системы RAG** для базы знаний. | Использование базового поиска по ключевым словам или легковесных pre-trained моделей для начала, с возможностью усложнения логики при наличии времени. |
